Figure 1 — Conceptual Architecture: Four Independent Edge-AI Modules

A Decentralised, Edge-Native AI Framework for Sustainable Hiking Tourism in Sri Lanka · hardware-free · offline-first

Hiker's smartphone — on-device, offline (real time)

Module 1 · Terrain & Effortphone · real-time

InputIMU (accel + gyro) · GPS distance · barometric/DEM elevation
ProcessQuantised CNN-LSTM terrain classifier (2.56 s windows, fixed phone position) + Naismith/Tobler energy-expenditure effort model
OutputTerrain-difficulty tags + personal "rest / turn-back" fatigue gauge

Module 2 · Visionphone · real-time

InputGround-level RGB frames, sampled 1–2 fps
ProcessINT8 YOLOv8-seg: litter detection + degradation segmentation (erosion, roots) with ClutterScore noise filter
OutputGeotagged litter counts + trail-degradation map

Module 3 · Hiker Assistantoffline · on-device RAG

InputCurated knowledge base (rules, safety, trails, species, fair-price info) cached on device
ProcessLocal semantic search + small quantised LLM answers using only retrieved trusted text (RAG), with source shown
OutputShort, grounded, source-cited answers (safety / rules / trail)

Module 4 · Crowd & Carrying-Capacityback-end · standalone

InputOpenStreetMap trail graph · Copernicus GLO-30 DEM (slope, TWI) · ERA5 weather/seasonality
ProcessST-GNN (GCN + temporal LSTM, adaptive attention); foot-traffic proxy-modelled (permit caps × seasonality), calibrated & baselined
OutputBottleneck forecasts + dynamic Effective Carrying Capacity (ECC) recommendations

Independent peers — no module consumes another's output. Module 4 is fully standalone (no arrows between modules).

KB-scale derived telemetry only (tags · scores · GPS · timestamps) ⟶ synced when online ⟶
Optional shared dashboard
Trail condition (M1 + M2) · Hiker assistant (M3) · Crowd & dynamic ECC (M4) — display only, not a dependency
Privacy-by-design: all raw IMU streams and images are processed locally and never leave the device; only kilobyte-scale derived features sync opportunistically.   No IoT hardware is deployed in the park; no cloud connectivity is required on-trail.

Figure 1. Four self-contained edge-AI modules. Modules 1–2 run in real time on the hiker's phone; Module 3 runs offline on cached text; Module 4 is a standalone back-end forecaster using only open geospatial/weather data. The modules are loosely coupled — an optional dashboard merely displays their outputs together.
